# OpenWiki Server 功能清单

> 将 LangChain OpenWiki 封装为独立对外服务的 Wiki 引擎，供 open-ikc 消费；对外提供 HTTP / gRPC / Celery / MCP / CLI 五类接口。

| 一级功能 | 二级功能 | 功能描述 |
| --- | --- | --- |
| 一、Wiki 实例管理 | 创建 Wiki 实例 | 按 `kbId` 创建 wiki 实例，校验并归一化 `wikiConfig`，自动派生稳定 `wikiId`（`wiki_ + sha1(kbId)[:12]`），支持指定 `tenantId`/`ownerId` 实现归属划分 |
| 一、Wiki 实例管理 | 查询实例元信息 | 按 `wikiId` 获取单个 wiki 实例的元数据（库名、配置、时间戳等） |
| 一、Wiki 实例管理 | 列出 Wiki 实例 | 列举全部实例，支持按 `tenantId`、`ownerId` 过滤 |
| 一、Wiki 实例管理 | 删除 Wiki 实例 | 删除实例并级联清理其页面记录与文件产物 |
| 一、Wiki 实例管理 | 稳定 ID 生成 | 与 open-ikc 完全兼容的 ID 派生规则：`wikiId = sha1(kbId)[:12]`、`pageId = sha1(kbId:stableKey)[:12]`，保证跨系统 ID 一致 |
| 二、文档加工与知识抽取 | 按文档建页（build） | 核心加工入口：将 Markdown 文档切页、抽取字段、生成页面记录并入库；OpenWiki 内核可用时走 LLM 合成，否则降级为规则切页 |
| 二、文档加工与知识抽取 | 增量合并（merge） | 对已有页面记录按稳定键增量 upsert，支持 merge/overwrite/skip 三种去重口径 |
| 二、文档加工与知识抽取 | 按文档废弃（deprecate-doc） | 按 `docId` 增量废弃该文档产出的页面，标记为 `deprecated` 而非物理删除 |
| 二、文档加工与知识抽取 | 全量刷新（update） | 调用 OpenWiki 内核 `personal --update`，基于 LLM 对实例做全量增量重合成 |
| 二、文档加工与知识抽取 | 连接器摄取（ingest） | 调用内核 `ingest <connector>`，支持 git-repo / web-search / notion 等外部数据源接入 |
| 二、文档加工与知识抽取 | 多来源溯源 | 每个页面记录维护 `sourceDocs`（来源 docId 列表），支持跨文档合并时的来源追溯 |
| 二、文档加工与知识抽取 | 页面互链抽取 | 自动解析 `[[wiki 链接]]` 与 `[文本](xxx.md)` 两类链接，按 `linkMode` 生成页面间引用关系 |
| 三、查询与检索 | 页面树查询（tree） | 返回库级分层页面树（h1 为根、h2 逐级挂载），支持分页（page / pageSize） |
| 三、查询与检索 | 页面详情（page） | 按 `pageId` 获取单页完整内容（markdown、字段、标签、链接、状态等） |
| 三、查询与检索 | 内容检索（search） | 按关键词 `q` + 标签 `tag` 检索页面，返回带摘要（snippet）与相关度评分的命中列表，支持 limit |
| 三、查询与检索 | 统计信息（stat） | 返回 wiki 的页面数量、活跃/废弃等统计概览 |
| 三、查询与检索 | 导出（export） | 将全部页面导出为 `jsonl` 或 `json` 格式 |
| 四、异步任务与作业调度 | 异步作业登记（submit_job） | 请求带 `async=1` 时，将 build/merge/export 等操作登记为 job，返回 `jobId`，状态置 `pending` |
| 四、异步任务与作业调度 | Celery broker 投递 | 登记后投递至 Redis broker；broker 不可达或未配置时保持 `pending`，不静默丢失（含缺 redis-py 的失败原因日志） |
| 四、异步任务与作业调度 | 作业手动执行（run_job） | 同步执行已登记任务，供 HTTP `jobs/{id}/run` 与 worker 复用；终态统一回写（成功 `success`+result / 失败 `failed`+error） |
| 四、异步任务与作业调度 | 作业状态查询（get_job） | 按 `jobId` 轮询作业状态与结果 |
| 四、异步任务与作业调度 | 作业列表（list_jobs） | 按 wiki 列举作业，支持 limit |
| 四、异步任务与作业调度 | 六类异步任务 | Celery 任务：`openwiki_server.build / merge / deprecate_doc / export / update / ingest` |
| 五、多协议接口层 | HTTP 接口 | FastAPI，前缀 `/api/v1/wiki/*`，响应 envelope 与 open-ikc 对齐，统一错误码到 HTTP 状态映射（400/404/409/500） |
| 五、多协议接口层 | gRPC 接口 | `wiki.v1.WikiService`，动态 descriptor 实现，TCP 透传（默认端口 50052） |
| 五、多协议接口层 | Celery Worker 接口 | `openwiki-server serve worker`，消费 Redis 队列执行异步作业 |
| 五、多协议接口层 | MCP 接口 | stdio JSON-RPC 最小实现，支持 `initialize / tools/list / tools/call`，16 个工具与 HTTP/gRPC 语义一一对应 |
| 五、多协议接口层 | CLI 接口 | typer 命令行 `openwiki-server`，覆盖全部用例 + `serve` 启动，退出码 0/1/6 约定对齐 open-ikc |
| 五、多协议接口层 | 健康与就绪探针 | `GET /health`、`GET /ready`（探针请求不进日志中心，避免淹没业务日志） |
| 五、多协议接口层 | 链路追踪 | HTTP 中间件绑定/透传 `traceId`（`TRACE_ID_HEADER`），贯穿请求-响应 envelope |
| 六、OpenWiki 内核集成与守卫式降级 | 内核子进程调用 | 以子进程方式调用 Node CLI `openwiki`（`personal --update` / `ingest`），支持 provider / model_id / timeout 配置 |
| 六、OpenWiki 内核集成与守卫式降级 | 多租户隔离 | `HOME` 环境变量指向各 wiki 实例目录，使内核配置与产物（`~/.openwiki`）落在实例内互不干扰 |
| 六、OpenWiki 内核集成与守卫式降级 | OKF v0.2 解析 | 解析内核产出的 Markdown：YAML front matter（type/tags/sources/status/扩展字段）+ 正文 + 页面互链 |
| 六、OpenWiki 内核集成与守卫式降级 | 守卫式降级 | 内核未安装 / LLM 失败 / 无网络时，`build_from_doc` 自动切换为确定性规则切页，全链路离线可用 |
| 六、OpenWiki 内核集成与守卫式降级 | 规则切页 | 按 `granularity`（page / heading / section / auto）切页；auto 依标题层级回退，保证无标题也能成页 |
| 六、OpenWiki 内核集成与守卫式降级 | 结构化字段抽取 | 按 `extractFields` 白名单从正文抽取「字段：值」行为结构化字段 |
| 六、OpenWiki 内核集成与守卫式降级 | 内核可用性检测 | 依配置开关与二进制存在性判定内核是否可用，决定走 openwiki 还是 rule 模式 |
| 七、wikiConfig 配置能力 | 切页粒度（granularity） | 支持 auto / heading / section / page 四档 |
| 七、wikiConfig 配置能力 | 字段抽取（extractFields） | 字符串数组白名单，控制结构化字段抽取范围 |
| 七、wikiConfig 配置能力 | 链接模式（linkMode） | auto / off，控制页面互链是否自动抽取 |
| 七、wikiConfig 配置能力 | 去重策略（dedup） | merge / overwrite / skip，控制同稳定键页面的合并口径 |
| 七、wikiConfig 配置能力 | 模板（template） | 自由字符串模板配置 |
| 七、wikiConfig 配置能力 | 配置校验与归一化 | 缺省字段补默认值，非法枚举抛 `200001` 参数错误；支持实例级 + 任务级配置叠加 |
| 八、Core 数据面回写（open-ikc 接入） | 引擎→core 回写 | 构建后将已决策页面通过 `POST {base}/internal/wiki/build` 回写 core，落地版本递增、废弃、审计 |
| 八、Core 数据面回写（open-ikc 接入） | 契约字段投递 | 仅投递 core 契约字段（title/stableKey/level/tags/fields/links/sourceDocs/markdown 等），`parentPageId` 直接透传避免二次派生漂移 |
| 八、Core 数据面回写（open-ikc 接入） | 开关与降级 | 未配置 `IKC_CORE_BASE_URL` 时整体关闭（无副作用）；回写失败不阻断本地构建，返回 `writeback.ok=false` |
| 八、Core 数据面回写（open-ikc 接入） | 内部鉴权 | 请求头 `X-Internal-Token` 对齐 core `IKC_CORE_ADMIN_TOKEN` |
| 八、Core 数据面回写（open-ikc 接入） | 引擎版本标注 | 回写携带 `engine`/`engineVersion`（pyproject 版本优先，回落包元数据） |
| 九、应用集成 SDK | 同步客户端 | `OpenWikiServerClient`，`wikis.*` 与 `jobs.*` 领域方法覆盖全部能力，仅依赖 httpx |
| 九、应用集成 SDK | 异步客户端 | `AsyncOpenWikiServerClient`，与同步客户端共享同一套数据模型 |
| 九、应用集成 SDK | 环境变量引导 | `client_from_env()` 依 `OPENWIKI_SERVER_BASE_URL / TOKEN / USER_ID / TENANT_ID / ROLES` 构造 |
| 九、应用集成 SDK | Envelope 与异常层级 | 统一响应 envelope 解析、异常映射、trace 透传、请求头处理 |
| 九、应用集成 SDK | MockTransport 自测 | SDK 自带 36 例 MockTransport 单测与 quickstart 示例 |
| 十、部署与运维 | 单镜像多组件 | Python 引擎 + Node openwiki 内核 + HAProxy 代理层构建进同一 Docker 镜像 |
| 十、部署与运维 | HAProxy 统一入口 | 对外唯一入口：HTTP `:8080` 反代 uvicorn、gRPC `:50052` TCP 透传、stats `:8404`；引擎进程只听容器回环 |
| 十、部署与运维 | Docker 构建与冒烟 | `scripts/build_docker.sh` 构建、`docker compose up` 启动、`docker_smoke.sh` 7 项断言验证 |
| 十、部署与运维 | 离线镜像分发 | `docker save → 传输 → load → compose 启动` 的离线部署流程（deploy-offline） |
| 十、部署与运维 | PyPI 发布 | 引擎发布为 `openwiki-server`，SDK 独立发布为 `openwiki-server-sdk`，含 `publish-pypi.sh` |
| 十、部署与运维 | 远程日志投递 | IKC Log Center 远程投递（access/业务日志），含队列/批量/超时配置与 Celery fork 重建钩子 |
| 十、部署与运维 | 环境变量驱动配置 | `OPENWIKI_SERVER_*` 全量配置（数据目录/端口/broker/内核/LLM/日志），支持 `engine.yaml` 配置文件 |
| 十、部署与运维 | 数据卷持久化 | `app_data` 挂载 `/app/data`（SQLite + wiki 产物），worker 与 app 共用同一数据卷 |

## 溯源说明

本清单基于对以下真实代码的逐层核对梳理：

- **协议接口层**：`openwiki_engine/interfaces/`（http_app.py、cli.py、mcp_server.py、celery_app.py、grpc_server.py）
- **应用/领域/适配/持久层**：`application/service.py`、`domain/wiki_config.py`、`adapters/openwiki.py`、`adapters/core_writeback.py`、`persistence/sqlite_store.py`
- **部署与文档**：`README.md`、`docker/`、`scripts/`、`sdk/python/`
