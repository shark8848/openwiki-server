## 7. Celery 作业终态补齐（2026-09-16）

**问题**：`celery_app` 的 6 个任务只在**成功**时回写 job 表（原 `_finish_job`）——任务抛异常时
job 行不变，`status` 永远停在 `pending`，`GET /api/v1/wiki/jobs/{job_id}` 看不出失败，
调用方（ikc-core-service W-07 → 平台 → ikc-demo `pollJob`）只能靠轮询超时猜。

**改动**：`openwiki_engine/interfaces/celery_app.py` 把「执行 + 回写终态」收成一个 `_run_job(job_id, run)`：
成功 `update_job(status="success", result=result)`；异常 `update_job(status="failed", error=str(exc))`
后**原样向上抛**（Celery 仍标 FAILURE），不再有「异常路径不落库」的分支。6 个任务
（build / merge / deprecate_doc / export / update / ingest）改用该函数，任务体不再自己拼装回写。

**验证**：
- `tests/test_engine.py::test_celery_task_failure_marks_job_failed`：对不存在的 wiki 跑 `build_task`，
  作业落 `status=failed` + `error`（`result` 保持 `None`）；`pytest tests -q` → **34 passed**（基线 33 + 1）。
- 本机实测（HTTP `async=true` + 真实 Celery worker，broker `redis://127.0.0.1:6379/1`）：
  `POST /api/v1/wiki/wikis/wiki_missing/build {"async":true,...}` → `job_99262ea03a62` →
  轮询 2s 即得 `status=failed, error="Wiki 实例不存在", result=null`（修复前恒 `pending`）。

**环境提醒**：HTTP 进程与 worker 必须用带 `redis-py` 的解释器。本机 system `python3` 无 `redis-py`，
kombu 起不来 / `send_task` 直接失败，作业只登记不投递（日志 `未投递到 broker（broker 不可达？）`）——
症状与「任务未执行」完全相同，排查时先看图里有没有这条 warning。
