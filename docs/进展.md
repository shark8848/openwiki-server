## 7. Celery 作业终态补齐（2026-09-16）

**问题**：`celery_app` 的 6 个任务只在**成功**时回写 job 表（原 `_finish_job`）——任务抛异常时
job 行不变，`status` 永远停在 `pending`，`GET /api/v1/wiki/jobs/{job_id}` 看不出失败，
调用方（ikc-core-service W-07 → 平台 → ikc-demo `pollJob`）只能靠轮询超时猜。

**改动**：`openwiki_engine/interfaces/celery_app.py` 把「执行 + 回写终态」收成一个 `_run_job(job_id, run)`：
成功 `update_job(status="success", result=result)`；异常 `update_job(status="failed", error=str(exc))`
后**原样向上抛**（Celery 仍标 FAILURE），不再有「异常路径不落库」的分支。6 个任务
（build / merge / deprecate_doc / export / update / ingest）改用该函数，任务体不再自己拼装回写。

**验证**：
- `tests/test_engine.py::test_celery_task_failure_marks_job_failed`：对不存在的 wiki 跑 `build_task`，
  作业落 `status=failed` + `error`（`result` 保持 `None`）；`pytest tests -q` → **34 passed**（基线 33 + 1）。
- 本机实测（HTTP `async=true` + 真实 Celery worker，broker `redis://127.0.0.1:6379/1`）：
  `POST /api/v1/wiki/wikis/wiki_missing/build {"async":true,...}` → `job_99262ea03a62` →
  轮询 2s 即得 `status=failed, error="Wiki 实例不存在", result=null`（修复前恒 `pending`）。

**环境提醒**：HTTP 进程与 worker 必须用带 `redis-py` 的解释器。本机 system `python3` 无 `redis-py`，
kombu 起不来 / `send_task` 直接失败，作业只登记不投递（日志 `未投递到 broker（broker 不可达？）`）——
症状与「任务未执行」完全相同，排查时先看图里有没有这条 warning。

## 8. 一键离线发布 / 一键部署（2026-09-16）

**目标**：把「构建 → 导出 tar → 打包部署配置 →（可选）推送远端并拉起」收成两条命令，与 PyUploadX /
open-ikc / ikc_extraction 的既有约定对齐（`docker save` 产物命名 `<repo>_<tag>.tar`）。

**落地**：
- `scripts/publish-offline.sh`：本机侧一键（`--build` 走 `scripts/build_docker.sh --export`；打包
  `openwiki-server-compose-<version>.tgz` 与 `openwiki-server-<version>-SHA256SUMS.txt`；`--push` 用
  rsync/scp 推 `_release/` 并 ssh 执行远端部署脚本，rsync 与 ssh 共用 `SSH_PORT`）。版本取 `package.json`（1.0.0），并与
  `docker-compose.yml` 的 `image:` 一致性校验（不一致直接 fail，避免远端 `--no-build` 拉错镜像）。
- `scripts/deploy-remote.sh`：远端侧（`docker load` → 首次生成 `.env` → `compose up -d --no-build
  --force-recreate` → `/health` `/ready` 健康检查最多 90s），支持 `--check`（只看现状）、`--skip-load`、
  `--release-dir` / `--image` 覆盖。
- `config/env.remote.example`：远端 `.env` 模板（宿主端口、HAProxy stats、离线规则模式默认
  `OPENWIKI_SERVER_OPENWIKI=0`、LLM/LogCenter/Celery 可选段）。
- `docs/deploy-offline.md` §0 新增「一键发布 / 一键部署」入口；`scripts/docker_smoke.sh` 的 JSON 断言
  放宽为 `grep -E '"key"[: ]*value'`（引擎响应带空格时原断言误判）。

**提交前修掉的五处缺陷**（实跑发现）：
1. `deploy-remote.sh` 缺 `have()` 定义：一进脚本就 `have: command not found` → 报「未找到 docker」退出；
2. `--release-dir` / `--image` 带值参数解析：原 `for arg in "$@"` + `shift 2` 会把参数值当未知参数
   （而 `publish-offline.sh` 的远端调用正是这种写法），改为 `while [[ $# -gt 0 ]]` + `shift`；
3. 两个脚本的 `-h/--help`：原 awk 遇到 shebang 后的 `set -euo pipefail` 即 `exit`，帮助输出为空。
4. `deploy-remote.sh` 自动查找镜像 tar：`IMAGE_NAME="$(ls ... | head -1 | xargs -r basename)"` 在
   `set -e` + `pipefail` 下，`_release/` 无 tar 时 `ls` 非零即让整条赋值失败 → 脚本**静默退出
   （exit=2，零输出）**，到不了「未在 `_release/` 找到镜像 tar」的提示（正是「忘了传镜像」这个最常见
   的现场）；补 `|| true`，与紧邻的 `SUMS=...` 写法对齐。
5. `publish-offline.sh --push` 的 `rsync` 未带 `-e "ssh -p ${SSH_PORT}"`：`SSH_PORT` 非 22 时前两步
   ssh（建目录 / 跑部署脚本）走自定义端口、传输步骤却连 22，表现为「ssh 通、文件传不过去」的误导性
   失败；补 `-e` 保持同一端口。

**验证**：`bash -n` 两脚本通过；两个 `--help` 输出完整；`deploy-remote.sh` 空 `_release/` 时给出
「未在 `_release/` 找到镜像 tar」并 `exit=1`（修复前为静默 `exit=2`）；`--check`（构造 `_release/` 夹具）
哈希校验 `OK` + 列出现状 + `exit=0`，坏哈希 `exit=1` 中止；未知参数报错；`publish-offline.sh` 无参数时
用仓库已有 `docker/images/openwiki-server_1.0.0.tar` 实跑打包，bundle 内含
`docker-compose.yml / config/engine.example.yaml / config/env.remote.example / docs/deploy-offline.md /
scripts/deploy-remote.sh`，产物名/校验清单与手册一致（`docker/images/` 已 gitignore，未入库）。
